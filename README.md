# 🍽️ Smart QR Restaurant — QR-ভিত্তিক রেস্টুরেন্ট ম্যানেজমেন্ট সিস্টেম

কাস্টমার টেবিলে লাগানো QR কোড স্ক্যান করলেই তার ফোনে মেনু খুলবে, অর্ডার দেবে, বিল দেখবে — আর আপনি একটি অ্যাডমিন প্যানেল থেকে পুরো রেস্তোরাঁ চালাবেন: মেনু, কুপন, হ্যাপি আওয়ার, কিচেন ডিসপ্লে, রসিদ, জন্মদিন CRM — সবকিছু।

> 🌐 **লাইভ সাইট:** https://teantreat.vercel.app · অ্যাডমিন প্যানেল: `/admin` · কিচেন ডিসপ্লে: `/kds`
>
> 🎯 এই README-তে দুটো অংশ আছে — **(১)** সিস্টেমের ফিচার ও কাঠামো এক নজরে, **(২)** শূন্য থেকে লাইভ করার ধাপে ধাপে বাংলা গাইড (কোনো ইনস্টল/কমান্ড ছাড়াই, শুধু ব্রাউজারে ক্লিক করে)।

## ✨ ফিচার এক নজরে

### 📱 কাস্টমার সাইড
- **ক্যামেরা QR স্ক্যানার** — হোম পেজে টেবিল লিস্ট নেই; অ্যাপের ভেতর থেকেই ক্যামেরা (ব্যাক/ফ্রন্ট) দিয়ে টেবিলের QR স্ক্যান করে টেবিলে জয়েন। কেউ ইচ্ছে করে "অন্য" টেবিল বেছে নিতে পারে না (অ্যান্টি-স্ক্যাম)
- **শেয়ারড টেবিল সেশন** — একই টেবিলে যত জনের ফোনে স্ক্যান, সবাই একই সেশন ও একই বিলে
- **জিওফেন্স** — রেস্তোরাঁর নির্দিষ্ট এলাকার বাইরে থেকে স্ক্যান ব্লক
- মেনু: ক্যাটাগরি, সেট মেনু, **আপসেল (অ্যাড-অন সাজেশন) ড্রয়ার**, অ্যাড-অন, **হ্যাপি আওয়ার অটো-প্রাইসিং**, ছবি
- কুপন/ভাউচার স্লাইডার + কোড ইনপুট, লাইভ ডিসকাউন্ট
- ওয়েটার কল (পানি/পরিষ্কার/সহায়তা)
- চলমান বিল পেজ — রিটার্ন হওয়া আইটেম লাল ব্যাজে দেখায়
- ডিজিটাল রসিদ (`/receipt/[id]`)

### 🧾 বিলিং ও রিটার্ন
- অ্যাডমিন বিল নেওয়ার সময় **প্রতি আইটেমের পরিমাণ রিটার্ন (ফেরত) করা যায়** — রিটার্ন আইটেম বিল থেকে বাদ যায়
- **রিটার্ন হলে সেই অর্ডারের কুপন ছাড় অটো-বাতিল** — "অর্ডারে কুপনে সাশ্রয় + বিলে রিটার্ন" দ্বৈত স্ক্যাম বন্ধ
- রসিদ হিস্ট্রি: এডিট/ডিলিট (লেজারে অডিট এন্ট্রিসহ)
- **হ্যাশ-চেইন সিকিউরিটি লেজার** — সব গুরুত্বপূর্ণ ঘটনা টেম্পার-প্রুফভাবে জমা থাকে

### 🎟️ কুপন/ভাউচার
- ৪ ধরনের রুল: GENERAL · HOT_TIME (ফ্ল্যাশ ডিল) · SPECIAL_DAY · SET_MENU_QTY
- ক্যাম্পেইন লিমিট (মোট কতবার ব্যবহার যাবে) + **প্রতি ডিভাইসে একবারই ব্যবহার** (ডিভাইস আইডি + ফিঙ্গারপ্রিন্ট ডিডাপ — টেবিল বদলে রিট্রাই ব্লক)
- কাস্টমারকে দেখানো এরর মেসেজ **কোনো নিরাপত্তা মেকানিজম ফাঁস করে না**

### 👨‍🍳 কিচেন ডিসপ্লে (KDS)
- অর্ডার কিউ, স্টেটাস ট্রানজিশন (COOKING → READY → SERVED), প্রতিটি ধাপে আলাদা সাউন্ড
- **মোবাইল-ফ্রেন্ডলি সাউন্ড**: ট্যাপ করে অডিও আর্ম, WAV ফলব্যাক, স্ক্রিন জাগিয়ে রাখার Wake Lock
- নতুন অর্ডার/ওয়েটার কলে বিপ + টোস্ট

### 🧑‍💼 অ্যাডমিন প্যানেল
- ওভারভিউ (অটো-রিফ্রেশ), টেবিল ম্যানেজমেন্ট + **প্রিন্ট-রেডি QR ডাউনলোড** — কার্ডে রেস্তোরাঁর নাম (সেটিংস থেকে), লোগো, **বাংলা টেবিল নম্বর ও নির্দেশনা**, কোনো লিংক/URL দেখানো হয় না; বাংলা ফন্ট প্রজেক্টের সাথেই বান্ডিল করা (`assets/fonts`) তাই Vercel-এও লেখা নিখুঁত আসে
- মেনু CRUD + ImgBB ছবি আপলোড (মাল্টি-কি অটো-ফেইলওভার)
- হ্যাপি আওয়ার, কুপন, রসিদ হিস্ট্রি, সেটিংস (নাম/লোগো/টাইটেল সাফিক্স/"Powered by"/সেশনের মেয়াদ/জিওফেন্স/Public Base URL)
- **সাব-অ্যাডমিন অ্যাক্সেস কী** — কোন কর্মী কোন ট্যাব দেখবে তা পারমিশনে বাঁধা
- সাউন্ড টগল, Wake Lock, স্টেটাস চাইম

### 🎂 কাস্টমার CRM (ঐচ্ছিক)
- জন্মদিন/বার্ষিকী অফার, রেফারেল — প্রতিদিন রাত ১২টায় (ঢাকা) অটো ক্রন-জব
- Facebook Messenger ইন্টিগ্রেশনে অফার সরাসরি ইনবক্সে

|---|---|
| `/` | হোম — QR স্ক্যান গেটওয়ে (ক্যামেরা স্ক্যানার) |

## 🛡️ নিরাপত্তা ও অ্যান্টি-স্ক্যাম ব্যবস্থা

1. **HMAC-সাইনড সেশন কুকি** — সেশন ছাড়া মেনু/অর্ডার সম্ভব নয়; মেয়াদ শেষ হলে আবার স্ক্যান লাগবে
2. **জিওফেন্স** — রেস্তোরাঁর বাইরে থেকে অর্ডার ব্লক (`GEO_OUTSIDE`)
3. **কুপন ডিভাইস-ডিডাপ** — এক ডিভাইসে এক কুপন জীবনে একবারই; টেবিল ১-এ ব্যবহার করে টেবিল ২-এ আবার চেষ্টা → ব্লক + লেজার এন্ট্রি
4. **রিটার্নে কুপন অটো-বাতিল** — বিলে যেকোনো রিটার্ন হলে সেই সেশনের সব কুপন ছাড় শূন্য (সার্ভার-সাইডে এনফোর্সড)
5. **QR কার্ডে কোনো লিংক ছাপা হয় না** — কাস্টমার সিস্টেমের ভেতরের মেকানিজম শিখে স্ক্যাম করার সুযোগ কম
6. **হ্যাশ-চেইন লেজার** — কেউ ডাটাবেসে ঢুকে রেকর্ড বদলালে চেইন ভেঙে যায়, অ্যাডমিন প্যানেলে ধরা পড়ে
7. **সাব-অ্যাডমিন পারমিশন** — কর্মীর কী-তে যে ট্যাবগুলোর অনুমতি, শুধু সেগুলোই দেখে

## 🗺️ সিস্টেমটা কীভাবে কাজ করে (আগে বুঝুন)

আপনার পুরো সিস্টেম ৩টা জায়গায় ভাগ করা:

```
   GitHub.com                Vercel.com                 TiDB Cloud
  ┌──────────────┐        ┌──────────────────┐       ┌──────────────┐
  │  আপনার কোড   │  ───▶  │  ওয়েবসাইট চালায়  │ ◀──▶  │  সব ডাটা জমা  │
  │ (ফাইলের ভান্ডার) │ কপি নেয়  │ (খাবারের দোকানের  │ ডাটা নেয়  │ (টেবিল, মেনু, │
  └──────────────┘        │   হোস্টিং)        │       │ অর্ডার, বিল)  │
                          └──────────────────┘       └──────────────┘
                              ▲            ▲
                    কাস্টমারের ফোনে      আপনার ফোন/PC
                    QR স্ক্যান → মেনু        /admin প্যানেল
```

- **GitHub** = কোডের ভান্ডার। আপনার প্রজেক্টের সব ফাইল সেখানে জমা থাকবে।
- **Vercel** = ওয়েবসাইট চালানোর মেশিন। GitHub থেকে কোড নিয়ে নিজের সার্ভারে বসিয়ে ইন্টারনেটে চালু করে দেয়।
- **TiDB Cloud** = ডাটাবেস (MySQL)। মেনু, অর্ডার, বিল, সেটিংস — সব এখানে জমা হয়।

### "ডাটাবেস কানেক্ট" আসলে মানে কী?

একটা লাইনের ঠিকানা দিয়ে — তার নাম **`DATABASE_URL`**। এটা দেখতে এরকম:

```
mysql://ইউজারনেম:পাসওয়ার্ড@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/ডাটাবেসের-নাম?sslaccept=strict
```

ভেতরে যা যা আছে:

| অংশ | মানে |
|---|---|
| `mysql://` | ডাটাবেসের ধরন (MySQL) |
| `ইউজারনেম:পাসওয়ার্ড@` | ডাটাবেসে ঢোকার চাবি |
| `gateway01...tidbcloud.com` | TiDB সার্ভারের ঠিকানা |
| `:4000` | পোর্ট (TiDB-র নির্দিষ্ট দরজা — 4000-ই থাকবে, টাইপো নয়!) |
| `/ডাটাবেসের-নাম` | ডাটাবেসের নাম (যেকোনো নাম দেওয়া যায় — শুধু সব জায়গায় একই নাম ব্যবহার করতে হবে) |
| `?sslaccept=strict` | এনক্রিপ্টেড (নিরাপদ) কানেকশন — **অবশ্যই থাকতে হবে** |

এই এক লাইন আমরা **Vercel-এর "Environment Variables"** বক্সে বসিয়ে দেবো — ব্যস, এতেই Vercel আর TiDB জোড়া লাগে। আর কোনো সেটিং লাগে না। ✅

### "SQL Schema" মানে কী?

নতুন TiDB ডাটাবেস একদম খালি থাকে — যেন দরাজহীন আলমারি। **Schema** মানে সেই আলমারিতে দরাজ বানানো (ডাটাবেসের ভাষায় ২০+ টেবিল: `restaurant_tables`, `menu_items`, `orders`, `receipts`...)। আপনার প্রজেক্টে এই SQL আগেই তৈরি করে রাখা আছে — ফাইলের নাম **`tidb-schema.sql`**। শুধু TiDB-র ওয়েব কনসোলে কপি-পেস্ট করে Run চাপলেই সব দরাজ তৈরি হয়ে যাবে (ধাপ ৩)।

## 🗄️ ধাপ ২: ডাটাবেস কানেক্ট (২টা পথ)

### পথ A — আগে থেকে চালু TiDB-ই ব্যবহার করুন ⭐ (রেকমেন্ডেড)

আপনার `.env` ফাইলে যে `DATABASE_URL` লেখা আছে, সেটা একটা **চালু TiDB Cloud ক্লাস্টারের ঠিকানা** — এই ক্লাস্টারেই আপনার মেনু, টেবিল, সেটিংস, রসিদ **আগেই জমা আছে**।

- এই পথে: SQL Schema চালানো লাগবে **না**, মেনু নতুন করে ঢোকানো লাগবে **না** — সব ডাটা অটোমেটিক লাইভ সাইটে চলে আসবে 🎉
- করণীয় শুধু: `DATABASE_URL` লাইনটা ধাপ ৫-এ Vercel-এ বসানো। ব্যস!
- (শর্ত: ক্লাস্টারটা আপনার নিজের অ্যাকাউন্টের হতে হবে।)

### পথ B — একদম নতুন নিজের TiDB ক্লাস্টার বানালে

**B-১) অ্যাকাউন্ট খুলুন**
1. ব্রাউজারে যান: **https://tidbcloud.com**
2. **Sign up** → Google/GitHub অ্যাকাউন্ট দিয়ে লগইন করলেই হবে (সবচেয়ে সহজ)

**B-২) ক্লাস্টার বানান**
1. লগইনের পর **Create Cluster** বাটনে ক্লিক
2. প্ল্যান: **Serverless** (ফ্রি — এটাই বাছুন)
3. Region/Cloud: **AWS → ap-southeast-1 (Singapore)** — বাংলাদেশের কাছের অঞ্চল
4. Cluster Name দিন (যেমন `resturant`) → **Create** → ৩–৫ মিনিট অপেক্ষা (Status: **Active** হবে)

**B-৩) কানেকশন স্ট্রিং নিন**
1. ক্লাস্টারের পেজে **Connect** বাটনে ক্লিক
2. পাসওয়ার্ড চাইলে **Create password / Reset password** দিয়ে একটা পাসওয়ার্ড বানান → **কপি করে Notepad-এ সেভ করুন** (এটা আর দেখাবে না!)
3. Connect ডায়ালগে connection string পাবেন, এরকম:
   ```
   mysql://xxxxxxxxxx.root:YOUR_PASSWORD@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/test
   ```
4. শুধু **২টা জিনিস** বদলান:
   - শেষের `/test` → আপনার ডাটাবেসের নাম (যেমন `/resturant`) লিখুন
   - স্ট্রিং-এর একদম শেষে `?sslaccept=strict` যোগ করুন
   ```
   mysql://xxxxxxxxxx.root:YOUR_PASSWORD@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/resturant?sslaccept=strict
   ```
5. **এই পুরো লাইনটাই আপনার `DATABASE_URL`** — Notepad-এ সেভ করুন ✅

**B-৪) ডাটাবেস বানান**
1. TiDB Cloud-এ বাম মেনু থেকে **SQL Console** খুলুন (⚡ আইকন)
2. লিখুন: `CREATE DATABASE resturant;` → **Run** (বা Ctrl+Enter)
3. "OK / Executed successfully" দেখলেই শেষ → এবার ধাপ ৩-এ যান

> 📌 পথ B বেছে নিলে ডাটাবেস খালি থাকবে — সাইট লাইভ হওয়ার **পরে** (ধাপ ৬-এ) অ্যাডমিন প্যানেল থেকে রেস্তোরাঁর নাম, টেবিল, মেনু সব ঢোকাবেন।

## 🧱 ধাপ ৩: SQL Schema তৈরি করুন (নতুন ডাটাবেস হলে)

> ⏭️ **পথ A ব্যবহার করছেন? এই ধাপ স্কিপ করুন** — টেবিলগুলো আগেই আছে।


   | `IMGBB_KEYS` | ImgBB API কি (কমা দিয়ে একাধিক দেওয়া যায় — অটো-ফেইলওভার) | 🔵 ঐচ্ছিক |
   | `CRON_SECRET` | র‍্যান্ডম লেখা (জন্মদিন ক্রন-জবের সুরক্ষায়) | 🔵 ঐচ্ছিক |
   | `META_PAGE_ID` · `META_PAGE_TOKEN` · `META_VERIFY_TOKEN` | Messenger CRM সেটআপ করলে (নিচের ঐচ্ছিক অংশ) | 🔵 ঐচ্ছিক |

6. নিচে **Deploy** বাটনে ক্লিক → ⏳ ২–৪ মিনিট অপেক্ষা
7. 🎉 **Congratulations!** স্ক্রিনে আপনার সাইটের ঠিকানা: `https://resturant-app-আপনার-নাম.vercel.app`

### ৫.২) "ডাটাবেস কানেক্ট" আসলে এখানেই হয়ে গেল — কীভাবে?

- Vercel-এর সার্ভার চালু হওয়ার সময় `DATABASE_URL` ভ্যারিয়েবলটা পড়ে
- ওই ঠিকানা ধরে সরাসরি **আপনার TiDB Cloud ক্লাস্টারে** এনক্রিপ্টেড কানেকশন (`sslaccept=strict`) তৈরি করে
- তারপর সাইটের সব কাজ (মেনু দেখা, অর্ডার সেভ, বিল) সেই TiDB-তেই হয়
- **আলাদা কোনো ইনস্টল/ডাটাবেস বানানো লাগে না** ✅

> 💡 Vercel ফ্রি প্ল্যানে সার্ভার মূলত আমেরিকায়, TiDB সিঙ্গাপুরে — প্রতি রিকোয়েস্টে ~১০০ মিলিসেকেন্ড বাড়তি, সাধারণ ব্যবহারে বোঝা যায় না।

## 📘 ঐচ্ছিক: Messenger (Meta) সেটআপ

> না করলেও বাকি সব ফিচার চলবে। এটা করলে জন্মদিন/অকেশন অফার Messenger-এ যাবে। **ডিপ্লয় শেষ হওয়ার পরে** করবেন (https ঠিকানা লাগে)।

1. আপনার রেস্তোরাঁর একটা **Facebook Page** থাকতে হবে (username মনে রাখুন)
2. **https://developers.facebook.com** → My Apps → **Create App** → উদ্দেশ্য: **Business**
3. অ্যাপে **Add Product → Messenger → Set up**
4. **Messenger API Settings → Access Tokens** → Page সিলেক্ট করে **Generate Token** → টোকেন কপি
5. Vercel → Project → Settings → **Environment Variables**-এ যোগ করুন:
   - `META_PAGE_ID` = Page-এর ID
   - `META_PAGE_TOKEN` = কপি করা টোকেন
   - `META_VERIFY_TOKEN` = আপনার পছন্দের যেকোনো শব্দ (যেমন `my_shop_verify_99`)
   - সেভ করার পর **Deployments → সর্বশেষ ডিপ্লয়ে Redeploy** চাপুন
6. Messenger সেটিংসে **Webhooks → Edit**:
   - Callback URL: `https://আপনার-সাইট.vercel.app/api/webhook/messenger`
   - Verify Token: উপরের `META_VERIFY_TOKEN`-এর হুবহু মান
   - **Verify and Save** → ফিল্ড Subscribe: `messages`, `messaging_postbacks`, `referral` → Page-ও Subscribe করুন
7. `/admin` → **সেটিংস** → **m.me পেজ username** ফিল্ড + Messenger মাস্টার টগল ON ✅

## 🔐 নিরাপত্তা নোট

1. **`.env` কখনো কারও দেবেন না, GitHub-এ তুলবেন না** — এতে ডাটাবেস পাসওয়ার্ড আছে। ভুলে আপলোড হলে সাথে সাথে TiDB পাসওয়ার্ড **Reset** করুন।
2. **ডিফল্ট পাসকোড বদলান** — `ADMIN_PASSCODE=admin123` রেখে দেবেন না। কর্মীদের মেইন পাসকোড নয় — **অ্যাক্সেস কী ট্যাব** থেকে সাব-অ্যাডমিন কি বানিয়ে দিন (কোন ট্যাব দেখবে তা চেকবক্সে মার্ক করে)।
3. **কর্মীর চাকরি শেষ হলে** তার কি নিষ্ক্রিয়/ডিলিট করুন।
4. **বিল নেওয়ার পর টেবিল ক্লিয়ার করুন** — পুরনো QR লিঙ্ক কেউ পেলেও ব্যবহার করতে পারবে না।
5. **জিওফেন্স চালু রাখুন** — সঠিক পিন + বাইরের ব্যাসার্ধ (যেমন ১৫০–৩০০ মিটার); ঘরে বসে জাল অর্ডার দেওয়া যাবে না।
6. **সিকিউরিটি লেজার** — সব ঘটনা হ্যাশ-চেইনে জমা হয়; রেকর্ড বদলালে অ্যাডমিন প্যানেলেই ধরা পড়ে।
7. **SESSION_SECRET পরে বদলালে** সব চলমান QR সেশন বাতিল হবে (নিরাপত্তার জন্যই)।
