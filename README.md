# 🍽️ Smart QR Restaurant — অনলাইনে লাইভ করার সহজ গাইড
### (TiDB ডাটাবেস কানেক্ট + SQL Schema + GitHub আপলোড + Vercel পাবলিশ)

রেস্তোরাঁর টেবিলে লাগানো QR কোড কাস্টমার স্ক্যান করলেই তার ফোনে মেনু খুলবে, অর্ডার দেবে, লাইভ ট্র্যাক করবে — আর আপনি একটি অ্যাডমিন প্যানেল থেকে পুরো রেস্তোরাঁ চালাবেন।

> 🎯 **এই গাইডে আপনার ল্যাপটপে কিছুই ইনস্টল করা লাগবে না।** কোনো Node.js, Git, টার্মিনাল-কমান্ড লাগবে না। সাইট চলবে Vercel-এর সার্ভারে (তারাই সব "চালানোর" কাজ করে), ডাটা থাকবে TiDB Cloud-এ, আর আপনি শুধু **ব্রাউজারে ক্লিক করে** সব সেটআপ করবেন।

## 🗺️ সিস্টেমটা কীভাবে কাজ করে (আগে বুঝুন)

আপনার পুরো সিস্টেম ৩টা জায়গায় ভাগ করা:

```
   GitHub.com                Vercel.com                 TiDB Cloud
  ┌──────────────┐        ┌──────────────────┐       ┌──────────────┐
  │  আপনার কোড   │  ───▶  │  ওয়েবসাইট চালায়  │ ◀──▶  │  সব ডাটা জমা  │
  │ (ফাইলের ভান্ডার) │ কপি নেয়  │ (খাবারের দোকানের  │ ডাটা নেয়  │ (টেবিল, মেনু, │
  └──────────────┘        │   হোস্টিং)        │       │ অর্ডার, বিল)  │
                          └──────────────────┘       └──────────────┘
                              ▲            ▲
                    কাস্টমারের ফোনে      আপনার ফোন/PC
                    QR স্ক্যান → মেনু        /admin প্যানেল
```

- **GitHub** = কোডের ভান্ডার। আপনার প্রজেক্টের সব ফাইল সেখানে জমা থাকবে।
- **Vercel** = ওয়েবসাইট চালানোর মেশিন। GitHub থেকে কোড নিয়ে নিজের সার্ভারে বসিয়ে ইন্টারনেটে চালু করে দেয়।
- **TiDB Cloud** = ডাটাবেস (MySQL)। মেনু, অর্ডার, বিল, সেটিংস — সব এখানে জমা হয়।

### "ডাটাবেস কানেক্ট" আসলে মানে কী?

একটা লাইনের ঠিকানা দিয়ে — তার নাম **`DATABASE_URL`**। এটা দেখতে এরকম:

```
mysql://ইউজারনেম:পাসওয়ার্ড@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/smart_qr_rest?sslaccept=strict
```

ভেতরে যা যা আছে:

| অংশ | মানে |
|---|---|
| `mysql://` | ডাটাবেসের ধরন (MySQL) |
| `ইউজারনেম:পাসওয়ার্ড@` | ডাটাবেসে ঢোকার চাবি |
| `gateway01...tidbcloud.com` | TiDB সার্ভারের ঠিকানা |
| `:4000` | পোর্ট (TiDB-র নির্দিষ্ট দরজা — 4000-ই থাকবে, টাইপো নয়!) |
| `/smart_qr_rest` | ডাটাবেসের নাম |
| `?sslaccept=strict` | এনক্রিপ্টেড (নিরাপদ) কানেকশন — **অবশ্যই থাকতে হবে** |

এই এক লাইন আমরা **Vercel-এর "Environment Variables"** বক্সে বসিয়ে দেবো — ব্যস, এতেই Vercel আর TiDB জোড়া লাগে। আর কোনো সেটিং লাগে না। ✅

### "SQL Schema" মানে কী?

নতুন TiDB ডাটাবেস একদম খালি থাকে — যেন দরাজহীন আলমারি। **Schema** মানে সেই আলমারিতে দরাজ বানানো (ডাটাবেসের ভাষায় ২০টা টেবিল: `tables`, `menu_items`, `orders`, `receipts`...)। আপনার প্রজেক্টে এই SQL আগেই তৈরি করে রাখা আছে — ফাইলের নাম **`tidb-schema.sql`**। শুধু TiDB-র ওয়েব কনসোলে কপি-পেস্ট করে Run চাপলেই সব দরাজ তৈরি হয়ে যাবে (ধাপ ৩)।

## 🗄️ ধাপ ২: ডাটাবেস কানেক্ট (২টা পথ)

### পথ A — সবচেয়ে সহজ: আগে থেকে চালু TiDB-ই ব্যবহার করুন ⭐ (রেকমেন্ডেড)

আপনার প্রজেক্টের `.env` ফাইলে যে `DATABASE_URL` লেখা আছে, সেটা একটা **চালু TiDB Cloud ক্লাস্টারের ঠিকানা** — এই ক্লাস্টারেই আপনার মেনু, টেবিল, সেটিংস, রসিদ **আগেই জমা আছে**।

- এই পথে: SQL Schema চালানো লাগবে **না**, মেনু নতুন করে ঢোকানো লাগবে **না** — সব ডাটা অটোমেটিক লাইভ সাইটে চলে আসবে 🎉
- করণীয় শুধু: ধাপ ১-এ কপি করা `DATABASE_URL` লাইনটা ধাপ ৫-এ Vercel-এ বসানো। ব্যস!
- (শর্ত: এই ক্লাস্টারটা যেন আপনার নিজের অ্যাকাউন্টের হয়, আর TiDB free কোটা চলতে থাকে।)

### পথ B — একদম নতুন নিজের TiDB ক্লাস্টার বানালে

**B-১) অ্যাকাউন্ট খুলুন**
1. ব্রাউজারে যান: **https://tidbcloud.com**
2. **Sign up** → Google/GitHub অ্যাকাউন্ট দিয়ে লগইন করলেই হবে (সবচেয়ে সহজ)

**B-২) ক্লাস্টার বানান**
1. লগইনের পর **Create Cluster** বাটনে ক্লিক
2. প্ল্যান: **Serverless** (ফ্রি — এটাই বাছুন)
3. Region/Cloud: **AWS → ap-southeast-1 (Singapore)** — বাংলাদেশের কাছের অঞ্চল
4. Cluster Name দিন (যেমন `restaurant`) → **Create** → ৩–৫ মিনিট অপেক্ষা (Status: **Active** হবে)

**B-৩) কানেকশন স্ট্রিং নিন**
1. ক্লাস্টারের পেজে **Connect** বাটনে ক্লিক
2. পাসওয়ার্ড চাইলে **Create password / Reset password** দিয়ে একটা পাসওয়ার্ড বানান → **কপি করে Notepad-এ সেভ করুন** (এটা আর দেখাবে না!)
3. Connect ডায়ালগে connection string পাবেন, এরকম:
   ```
   mysql://xxxxxxxxxx.root:YOUR_PASSWORD@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/test
   ```
4. শুধু **২টা জিনিস** বদলান:
   - শেষের `/test` → `/smart_qr_rest` লিখুন
   - স্ট্রিং-এর একদম শেষে `?sslaccept=strict` যোগ করুন
   ```
   mysql://xxxxxxxxxx.root:YOUR_PASSWORD@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/smart_qr_rest?sslaccept=strict
   ```
5. **এই পুরো লাইনটাই আপনার `DATABASE_URL`** — Notepad-এ সেভ করুন ✅

**B-৪) ডাটাবেস বানান**
1. TiDB Cloud-এ বাম মেনু থেকে **SQL Console** খুলুন (⚡ আইকন)
2. লিখুন: `CREATE DATABASE smart_qr_rest;` → **Run** (বা Ctrl+Enter)
3. "OK / Executed successfully" দেখলেই শেষ → এবার ধাপ ৩-এ যান

> 📌 পথ B বেছে নিলে ডাটাবেস খালি থাকবে — সাইট লাইভ হওয়ার **পরে** (ধাপ ৬-এ) অ্যাডমিন প্যানেল থেকে রেস্তোরাঁর নাম, টেবিল, মেনু সব ঢোকাবেন।

## 🧱 ধাপ ৩: SQL Schema তৈরি করুন (নতুন ডাটাবেস হলে)

> ⏭️ **পথ A ব্যবহার করছেন? এই ধাপ স্কিপ করুন** — টেবিলগুলো আগেই আছে।

1. প্রজেক্ট ফোল্ডারের **`tidb-schema.sql`** ফাইলটা **Notepad** দিয়ে খুলুন
2. **সব লেখা সিলেক্ট করে কপি** করুন (Ctrl+A → Ctrl+C)
3. TiDB Cloud → **SQL Console** খুলুন → **পেস্ট** করুন (Ctrl+V)
4. উপরে/ডানে ডাটাবেস সিলেক্ট ড্রপডাউন থাকলে **`smart_qr_rest`** বাছুন (কনসোলের শুরুতে `USE smart_qr_rest;` আগেই লেখা আছে)
5. **Run** (বা Ctrl+Enter) চাপুন
6. শেষ হলে ✅ — এবার যাচাই করুন, কনসোলে লিখুন:
   ```sql
   SHOW TABLES;
   ```
   ২০টা টেবিলের নাম দেখলেই কাজ শেষ 🎉

### কী কী টেবিল তৈরি হলো? (এক নজরে)

| টেবিল | কী জমা থাকে |
|---|---|
| `tables`, `table_sessions`, `session_devices` | রেস্তোরাঁর টেবিল, QR সেশন, কোন ফোন কোন সেশনে |
| `categories`, `menu_items` | মেনুর ক্যাটাগরি ও খাবার |
| `orders`, `order_items` | অর্ডার ও অর্ডারের আইটেম |

## 📘 ঐচ্ছিক: Messenger (Meta) সেটআপ

> না করলেও বাকি সব ফিচার চলবে। এটা করলে জন্মদিন/অকেশন অফার Messenger-এ যাবে। **ডিপ্লয় শেষ হওয়ার পরে** করবেন (https ঠিকানা লাগে)।

1. আপনার রেস্তোরাঁর একটা **Facebook Page** থাকতে হবে (username মনে রাখুন, যেমন `facebook.com/SpiceGardenBD`)
2. **https://developers.facebook.com** → My Apps → **Create App** → উদ্দেশ্য: **Business**
3. অ্যাপে **Add Product → Messenger → Set up**
4. **Messenger API Settings → Access Tokens** → আপনার Page সিলেক্ট করে **Generate Token** → টোকেন কপি
5. Vercel → আপনার Project → Settings → **Environment Variables**-এ যোগ করুন:
   - `META_PAGE_ID` = Page-এর ID (Page → About-এ পাবেন)
   - `META_PAGE_TOKEN` = কপি করা টোকেন
   - `META_VERIFY_TOKEN` = আপনার পছন্দের যেকোনো শব্দ (যেমন `my_shop_verify_99`)
   - সেভ করার পর **Deployments ট্যাবে গিয়ে সর্বশেষ ডিপ্লয়ে Redeploy** চাপুন (নতুন ভ্যারিয়েবল কাজে দিতে)
6. Messenger সেটিংসে **Webhooks → Edit**:
   - Callback URL: `https://আপনার-সাইট.vercel.app/api/webhook/messenger`
   - Verify Token: উপরের `META_VERIFY_TOKEN`-এর হুবহু মান
   - **Verify and Save** → ফিল্ড Subscribe: `messages`, `messaging_postbacks`, `referral` → Page-ও Subscribe করুন
7. `/admin` → **সেটিংস** → **m.me পেজ username** ফিল্ডে পেজের username দিন + Messenger মাস্টার টগল ON ✅

| সাইট খোলে কিন্তু মেনু/ডাটা খালি | পথ B হলে এটা স্বাভাবিক — অ্যাডমিন প্যানেল থেকে মেনু ঢোকান; পথ A হলে `DATABASE_URL`-এর শেষের ডাটাবেস নাম `/smart_qr_rest` কি না দেখুন |
| `Table does not exist` | ধাপ ৩-এর SQL চালাননি — TiDB SQL Console-এ `tidb-schema.sql` পেস্ট করে Run করুন |
| Vercel-এ পেজে 500 | Vercel → Project → **Logs** দেখুন; `DATABASE_URL`-এ `&connection_limit=1` যোগ করে **Redeploy** করুন |
| QR স্ক্যানে **localhost** খোলে | অ্যাডমিন → সেটিংস → **Public Base URL**-এ আসল ঠিকানা দিন → QR আবার ডাউনলোড করুন (ধাপ ৬.৩) |

| KDS-এ সাউন্ড নেই | একবার "সাউন্ড চালু করুন" বাটনে ক্লিক করা লাগে (ব্রাউজারের নিয়ম) |

| অর্ডার নম্বর লাফিয়ে যায় | TiDB-র AUTO_INCREMENT আচরণ — স্বাভাবিক, ক্ষতি নেই |

## 🔐 নিরাপত্তা নোট

1. **`.env` কখনো কারও দেবেন না, GitHub-এ তুলবেন না** — এতে ডাটাবেস পাসওয়ার্ড আছে। ভুলে আপলোড হয়ে গেলে সাথে সাথে TiDB-র পাসওয়ার্ড **Reset** করুন।
2. **ডিফল্ট পাসকোড বদলান** — `ADMIN_PASSCODE=admin123` রেখে দেবেন না। কর্মীদের মেইন পাসকোড নয় — **অ্যাক্সেস কী ট্যাব** থেকে সাব-অ্যাডমিন কি বানিয়ে দিন (কোন ট্যাব দেখবে তা চেকবক্সে মার্ক করে)।
3. **কর্মীর চাকরি শেষ হলে** তার কি নিষ্ক্রিয়/ডিলিট করুন (অ্যাক্সেস কী ট্যাব)।
4. **বিল নেওয়ার পর টেবিল ক্লিয়ার করুন** — পুরনো QR লিঙ্ক কেউ পেলেও ব্যবহার করতে পারবে না।
5. **জিওফেন্স চালু রাখুন** — রেস্তোরাঁর ঠিক লোকেশনে পিন + বাইরের ব্যাসার্ধ (যেমন ১৫০–৩০০ মিটার); ঘরে বসে কেউ জাল অর্ডার দিতে পারবে না।
6. **সিকিউরিটি লেজার** — সব ঘটনা হ্যাশ-চেইনে জমা হয়; কেউ ডাটাবেসে ঢুকে রেকর্ড বদলালে অ্যাডমিন প্যানেলেই ধরা পড়ে।
7. **SESSION_SECRET পরে বদলালে** সব চলমান QR সেশন বাতিল হবে (নিরাপত্তার জন্যই)।
